# 数字兼容性实验：不将词面过滤升级为语义拒答

## 本批决定

仍不修改生产检索。PR32 的覆盖率实验说明无答案拒答改善可能掩盖有答案召回损失；本次只检查另一个可复现假设：版本、日期、数量的词面不匹配能否更保守地过滤误召回。

## 新冻结对照

不调试已曝光的 v3 留出集。新增 v4 开发集20题/8快照，独立作者留出集26题/10快照，使用新实体。留出作者未运行检索、未看结果即交付并冻结；实现、协议和两集在首次运行前本地提交。文件SHA256进入测试及JSON。作者分离不是盲测组织、独立人工裁决或真实世界样本。

预设三种策略，均只过滤生产 lexical 前5条，不补位、不重排：

- baseline：不额外过滤。
- reject_disjoint：问题与文档都含阿拉伯数字时，要求数字集合至少有交集；一方无数字则保留。
- require_all：要求问题中的每个数字词面都出现在单条文档标题或全文。

数字词面为 ASCII 数字及点分版本，不转换中文数字、单位、日期格式；不理解数字属于哪个属性。选择只用开发集：每道有答案题及宏平均Recall都不得下降，再最大化无答案拒答，同分按上述顺序取前。留出只诊断，不能改选策略。

## 首次观察

| 策略 | 开发Recall（12题） | 开发无答案拒答（8题） | 留出Recall（17题） | 留出无答案拒答（9题） |
|---|---:|---:|---:|---:|
| baseline | 100% | 12.5% | 100% | 0% |
| reject_disjoint | 79.17% | 25% | 100% | 0% |
| require_all | 70.83% | 50% | 82.35% | 33.33% |

开发选择baseline。require_all在留出中增加3道无答案拒答，同时损失3道有答案题；不是可靠改善。reject_disjoint在留出既无新增召回损失，也无无答案拒答收益，不足以支持上线。

失败机制不是简单提高阈值能解决：

- “限额不是30次吗”可由20次原文纠正，数字不交集不代表证据无用。
- 比较多个对象时，一份材料通常只提供其中一个数字；要求每份包含全部数字会丢掉组成答案的材料。
- “十二次”与“12次”、日期不同写法可表达同一值，精确词面会误拒。
- 同一版本文档未提价格、许可证时，数字匹配仍不支持所问属性。
- 留出里混入共享实体的候选，过滤部分材料可能仍不触发空返回；单看拒答率看不到所有排名变化。

JSON同时保留每题移除ID、数字词面、召回损失/拒答收益ID和重叠标签分组。标签切片有重叠，不能相加当作独立样本数。

## 标注与范围限制

冻结标签是开发者判断，尚未独立语义裁决。已发现开发题 `n-dev-11` 有歧义：材料称“免费开放”，问“每月多少钱”也可能认为可以回答0，而原标签列为无答案。留出 `h4_retention/h4_compare` 的试用文档也写明正式期限，相关文档集合可能不穷尽，不能据此断言必须跨文档。保留原始数据和结果，不在看到结果后改标签或删除题；上述分数只能解释为**对冻结标签的符合程度**。该歧义进一步削弱上线依据，未来应先完成独立标注/分歧裁决再建新留出集，不能将这批数据当真实金标。

全部为合成资料和内存SQLite，无付费/真实embedding或用户数据。本批不评价生成答案；检索空返回不保证语义安全，引用位置一致不保证支持问题。v4首次结果公开后也转为回归集，不得当未见留出反复调参。下一步优先解决标注质量与独立语义评审，而不是再叠加数字词面特判。

复现：`cd backend && ../.venv/bin/python -m app.numeric_retrieval_eval --output /tmp/numeric-retrieval.json`。CI的 `synthetic-research-evaluation` artifact增加该JSON；生产检索配置保持不变。
