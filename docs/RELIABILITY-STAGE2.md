回归覆盖 UTC/Asia-Shanghai 当地跨日、UTC 跨日而当地不跨日、send 开关、手动任务，以及已完成 brief 的过期任务不重新生成。修复前两个跨日回归实际失败（错误状态 succeeded），修复后通过。

## 采集租约恢复补丁（0010）

新 durable 采集记录在首次写入时保存主任务 ID 与本次 lease token，并仍由同一 fence 保护提交。恢复者赢得主 Run 的条件更新后，在同一事务中只把该 run/token 下仍 running 的 FetchRun 标为 interrupted，记录完成时间与脱敏原因。不会改动来源健康、已成功证据、其他尝试或已终态采集。事务失败同时回滚主任务与采集状态。

故障注入覆盖旧抓取晚返回成功/失败、新尝试先成功、两个恢复者竞争、进程崩溃重试/耗尽预算，以及恢复事务中途失败。0010 的 SQLite 带数据升级→降级→升级验证旧中文记录与外键；PostgreSQL CI 运行同一并发恢复测试及迁移往返。

升级前停止旧 API/Worker 并备份。0010 的关联列可空；旧版与非 durable 采集没有可靠 owner，不能猜测归属，因此不会自动标记历史孤立记录。该修复保证新关联尝试的接管清理，不保证取消已在途的网络请求，不绕过旧 worker 的 fencing。降级会移除新增关联信息，只在可丢弃测试库验证，不能用于生产回滚承诺。

## 计划日报投递期限（0011）

默认策略：**只对新建的定时日报 outbox 固定提交截止时间，采用该任务保存时区的次日当地零点，转换为 UTC 存储**。不是简单加 24 小时，也不是承诺午夜前送达。到期（含恰好到期）不再启动新的提交；pending/blocked_review 终结为 expired。审核通过、重试与已知未发送的人工恢复不能复活过期记录。发送端再次检查期限，SMTP 登录后、sendmail 前再检查一次。

已经开始提交的结果必须照实保留：接受为 sent，结果未知仍为 unknown，不因跨午夜改写成“没发”。确认已发送仍记 sent；确认未发送但已过期则 expired 而非重试。file 模式仍仅为本地预览，崩溃时可能已有同名文件，过期不会删除它，也不证明从未写入。

幂等键不变，同一简报/通道/收发件人重用首次记录与期限，不重新发送、不自动改期限。因此手动首次创建的同一记录无期限，后来定时任务重用它也不会追加期限；反之手动重复请求不会复活已过期的定时记录。此保守策略优先避免重复，若需要明确重发，应另行设计可审计的显式操作。

0011 新列对历史/手动记录保持 NULL，不猜测原计划日期，不能声称清理历史所有过期消息。页面展示期限（本机时区）与过期状态。UTC/上海、纽约夏令时、审核、假 SMTP 跨截止、重试退避、并发清理和人工判定均用隔离 fixture 回归，无真实邮件或供应商调用。实际升级前停旧 Worker 并备份；降级丢失期限，禁止以降级绕过到期保护。
