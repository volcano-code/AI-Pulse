# 标注与语义审核流程 v1

## 当前状态与范围

这是**AI辅助临时裁决流程**，不是人类审核或独立金标建设完成。三个历史歧义已给出可追踪建议，但仍可被证据反驳；同一系统的第二工作线程复核不算独立人类评审。生产检索与旧数据完全不变。

原始 v4 标签和hash保留。`backend/tests/fixtures/annotation_review_v1.json` 是单独版本化覆盖层，绑定来源版本/原文件SHA256、原问题与原相关集合。每条保存建议相关集合、最小充分证据集、精确引用/偏移、有限回答范围、理由及可证伪条件。修改裁决应新建 v2 而非覆盖 v1；不能把新标签结果冒充原留出测试分数。

## 可证伪的证据标准（evidence-support-v1）

1. **相关不等于充分**：相关文档可以只提供背景。充分集必须在明确题目范围内直接支持回答，或经注明的有限、确定运算支持回答。
2. **实体、属性、条件与时间对应**：同名主题、版本号命中本身不足；检查所问属性及账号/时期/单位，不能省略限定。
3. **有限推导**：允许已给定同单位数字的确定算术，如30−7=23；不能推断实际执行时间、未公布费用或未来承诺。
4. **拒答/证据不足**：如果所问事实不在允许范围证据中，标为不足；不能只因词面不匹配拒掉可纠正前提的材料。
5. **替代充分集**：一个完整证据集命中即可，不强制找齐所有相关材料。充分集合用列表表达OR，集合内部为AND；去掉重复集和冗余超集。
6. **可反驳**：每条必须说明哪些缺失条件、相反原文、实体不一致或时间/单位变化会使裁决失效。字符串非空校验不证明这些理由合理，仍需语义审阅。

## 三项建议

详见[逐项原文与裁决理由](ANNOTATION-ADJUDICATION-NOTES.md)。

- `n-dev-11`：当前描述“免费开放”支持有界回答无需付费，不能承诺未来或附加服务免费。由无答案改为临时有答案。
- `h4_retention`：补入直接说正式账号三十天的试用规则；归档器规则保留作背景。
- `h4_compare`：试用规则单篇已包含七天/三十天，足以计算二十三天。原相关集合保留，增加单篇最小充分集，撤销“必须两篇”的解释。

自动校验能验证来源hash、原标签、允许scope、精确字符位置及集合结构；不能证明语义支持。`sufficient_set_coverage_proxy`只是对临时标签集合的覆盖，不能称答案正确率。

## 可复用步骤

1. 先固定原始文件版本/hash与待审题。用 `app.annotation_review.draft_review(data, raw_bytes, case_ids, version)` 生成明确的 `draft`；未填写证据、范围、理由及可证伪条件不得通过校验。
2. 审阅者读取问题和允许scope中的完整快照，不先看候选策略优劣来选标签。填写相关集合、充分集和原文；记录AI来源。当前实现只接受 `ai_provisional`，并强制 `reviewer_kind=ai`、`human_review_completed=false`，拒绝直接改字段假充人类完成。
3. 使用 `validate_review`/`apply_review` 校验并生成深拷贝；原数据、原标签及原标签标签分类保留，不落盘覆盖原fixture。
4. 至少一次语义复核：逐条尝试反例；发现争议保留版本差异，记录分歧，不删除失败题美化分数。AI复核仍是AI。
5. 对新覆盖层计算旧/新指标并排显示，标为曝光后的标签敏感性分析。不要据此重新调原实验或宣称新的未见留出效果。
6. 真正的人类/独立审核仍待执行：需实际审核者读原文、确认/驳回具体决定，记录身份来源、日期、意见、冲突处理及版本。当前工具不认证人类身份，也不生成 `human_confirmed`；不能靠把JSON改成true完成这一步。

通用Python函数可处理兼容合成数据；CLI默认注册两份v4文件，新增来源须明确注册路径，不接受数据库连接、远程URL或执行代码。
