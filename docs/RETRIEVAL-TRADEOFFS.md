# 检索拒答与召回权衡：开发/留出合成实验

## 决定

**不修改生产检索阈值。** 证据不足以支持把简单词项覆盖率作为拒答保证。此批交付评测实验而非宣称修复语义相关性；用户仍须审核引用是否回答问题。

## 预先固定的方法

与 PR31 的12题基线分开，新建开发集（8快照、18题）与留出集（11快照、20题）。开发集和实验规则由一名开发者编写，留出集由另一个工作线程独立编写，未运行检索、未见指标即冻结。两集和规则在首次运行前提交；SHA256记录于运行报告及回归测试。检查题ID、问题文本、快照ID、文章ID、全文无交集。**独立作者不等于独立人工金标**；没有真实数据、独立裁决或统计泛化结论。公开运行后留出集转为回归集，不能反复调参仍声称“未见测试集”。

唯一候选：对生产 lexical 已返回的前5条，计算问题的不同词项在快照标题+全文中的覆盖比例，再过滤。不重排、不补位、不使用答案标签。阈值网格预先固定为 0、0.25、0.5、0.75、1。开发选择规则：宏平均Recall@5不得低于开发基线，再最大化无答案检索拒答率，同分取最小阈值。留出标签不参与选择；额外展示完整留出网格只用于揭示权衡，禁止据此重新选阈值。

## 首次结果

| 阈值 | 开发 Recall@5（11题） | 开发无答案拒答（7题） | 留出 Recall@5（11题） | 留出无答案拒答（9题） |
|---|---:|---:|---:|---:|
| 0 | 90.91% | 14.29% | 100% | 33.33% |
| 0.25 | 90.91% | 14.29% | 77.27% | 44.44% |
| 0.5 | 72.73% | 57.14% | 45.45% | 100% |
| 0.75 | 9.09% | 100% | 36.36% | 100% |
| 1 | 9.09% | 100% | 0% | 100% |

开发规则选择 **0（维持基线）**。词汇不全相同的正确材料也会被覆盖率过滤；高阈值制造漂亮拒答率同时拒掉有答案问题。留出0.5时11道有答案题中6题空返回；1.0时全部空返回。不能只报100%拒答而隐藏召回损失。0.25即使开发无损，也不能据此保证留出无损。

无答案主题重叠、版本/时间限定、同义表达都说明“命中词项”与“支持回答”不同。本实验不引入针对实体、价格词或固定题目的特判；未修改原始标签或删掉失败案例。

## 复现与范围

仓库根目录：`cd backend && ../.venv/bin/python -m app.retrieval_tradeoffs --output /tmp/retrieval-tradeoffs.json`。CI产出 `synthetic-research-evaluation` artifact，其中包含原基线及本次分拆报告。运行器只建SQLite内存库，不读取用户数据库或调用供应商。记录实际 requested/effective mode；hybrid在SQLite降级为lexical，**真实embedding未测**。实验只对lexical候选做后过滤，不称作向量对比。

JSON记录每题过滤前后ID、词项覆盖、标签、指标和数据/规则哈希。无答案题不进入Recall/MRR分母；有答案空返回单独计数。检索拒答不等于生成答案无幻觉，引用字符相等不等于语义支持。未生成答案、未人工语义评审，因此两项质量指标均不能宣称完成。

下一步应获得独立真实/更广分布标注及语义相关性评审，再比较真正语义检索或可校准的拒答策略。新策略需要新冻结留出集；本次不支持把简单覆盖率阈值上线。
